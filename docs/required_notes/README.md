# Notes `docs/RESULTS.md` must carry

`docs/RESULTS.md` is generated by `salvage eval report`, which renders `_limitations()` in
`salvage/eval/report.py`. A limitation added to the generated file by hand survives until the next
regeneration and then disappears without a word, which is the same failure mode as the stale
artifacts `check_freshness()` exists to catch: the document keeps looking complete while something
a reader would act on has quietly left it.

Every `*.note.md` file in this directory is the canonical text of one such note.
`test_results_still_carries_every_required_note` in `tests/unit/test_docs_claims.py` asserts each
one appears verbatim in `docs/RESULTS.md` and fails loudly, by name, when one does not.

If that test fails after a regeneration, paste the file's contents back into the limitations
section of `docs/RESULTS.md`. That is the stopgap. The fix is to add the same text to the `items`
list in `_limitations()` so the generator emits it, and to delete the note file, at which point
the guard has nothing left to guard. That change is deferred while the build is frozen; see the
post-freeze entry in `docs/BUILD_LOG.md`.

A note file is the exact text of one Markdown list item, one line, no trailing prose.
